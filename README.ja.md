> ## ⚠️ プロジェクト状況：開発初期、まだ使用できません
>
> **本番利用や日々の自動化には使わないでください。** 現在も活発に開発中で、UI と API は予告なく変わります。また、**実機でのエンドツーエンドのタスク実行は一度も検証されていません**。
> 現状のコードは開発・実験・検証用途のみです。詳細は[ロードマップ](#ロードマップ)と [GitHub Issues](https://github.com/Kasbuky-sudo/maa-docker-web/issues) をご覧ください。

[MAA（MaaAssistantArknights）](https://github.com/MaaAssistantArknights/MaaAssistantArknights) 公式の
Linux ランタイムを、**x86_64 / arm64** の Docker 環境（NAS 向け）で動く Web 管理サービスとして包んだものです。

本リポジトリは MAA のバイナリ・リソースを**同梱しません**。ランタイムは MAA 公式 GitHub Release から
ダウンロードし、SHA-256 で検証したうえで永続ボリュームに展開します。

## バージョンと更新

| バージョン | 取得元 | 説明 |
|---|---|---|
| サーバーバージョン | `apps/maa-server/package.json` | **唯一の情報源**：タイトルバー・設定・アバウトは `GET /api/version` から取得し、各ページでのハードコードは廃止 |
| MAA ランタイムのバージョン | ディスク上のランタイム（`data/runtime` 内のマーカー） | 独立して更新可能：「更新を確認」は公式の最新リリースと比較し、**確認後にのみ**ダウンロード、公式 `assets[].digest` の SHA-256 で検証 |

ランタイムの更新にイメージの再ビルドは不要です。起動時にマーカーを読み、ランタイムが置き換わると
MaaCore のリソースキャッシュを破棄して旧セッションを切断します。

## できること / できないこと

✅ **実装済み**

- マルチアーキテクチャのイメージビルドとコンテナ運用（`linux/amd64` + `linux/arm64`、CI が ghcr に公開）
- 公式 MAA ランタイムのダウンロード / SHA-256 検証 / 展開 / 状態管理 / **公式リリースとのバージョン比較と更新**
- Web UI を windows-ui 公式コンポーネントで**全面書き直し**、バックエンドに接続済み：
  ホーム、タスクキュー（12 タスクと個別設定）、自動戦闘、スケジュール、ツール、ログ、設定
- バックエンド連携：実行状態のポーリング（2.5 秒）、タスク設定の永続化、キューの開始/停止、
  ログ（HTTP + WebSocket のライブ配信）、接続設定、システム情報、ランタイム/リソース検証
- 接続テスト：`AsstAsyncConnect`。**実機（Meizu 16X・無線 ADB）で確認済み**。
  エンドポイントは即座に応答し、進捗は状態ポーリングで取得（ゲートウェイタイムアウトを解消）。
  成功時は**セッションを保持**し、「開始」で再利用できます
- MaaCore のメッセージ ID はランタイム同梱のバインディングで一つずつ照合し、MaaCore の生のメッセージを UI に表示
- モバイル対応：760px 以下は 1 カラム、公式 `collapsed-float` のドロワー、横スクロールなし

- 認識系ツール**実装済み**：公開求人（Recruit）/ 倉庫（Depot）/ オペレーター（OperBox）を MaaCore で直接実行し、結果は公式コールバック構造（RecruitResult / DepotInfo / OperBoxInfo）で表示。実結果がない間は UI に「サンプルデータ」と明記
- 自動戦闘**実装済み**：ランタイム同梱の 76 個の公式ジョブ（SSS_ / Paradox_ プレフィックスで分類）を一覧化し、Copilot / SSSCopilot / ParadoxCopilot のプロトコル項目で実際に投入
- **理性作戦ウィークリープラン**：曜日ごとにステージを設定でき、サーバーが当日分を Fight タスクに展開
- **サーバー側スケジューラ**：daily / weekdays / weekends / 曜日指定、30 秒間隔、lastRun で二重実行防止
- **デバイスのライブ映像**：ADB screencap を PNG で配信（実機 1920×1080 で検証済み）。監視ページは目標 FPS で更新し、実測 FPS を表示

❌ **未対応**

- **実機でのタスク実行はまだ端到端で未検証**：接続 ✓・セッション保持 ✓・ウィークリープラン展開 ✓。「開始」ボタンは本物です。残りは実機での一回の実行だけ
- MAA 作業サイトのオンライン検索は未接続（ランタイム同梱ジョブとローカル解析のみ）
- 認識ツールの「Penguin-Statistics / ツールボックスへエクスポート」は未実装（結果は UI に表示）
- 接続設定以外の設定はサーバーに保存されません（`config.json` のホワイトリストは 4 項目）
- **認証なし**：信頼できる LAN でのみ使用してください

## 構成

```text
ブラウザ ──▶ maa-web (nginx) ──▶ maa-server (Node.js)
                                    ├── ランタイム管理（DL/検証/展開）
                                    ├── REST + WebSocket（ログ・タスク・状態）
                                    └── runner ──koffi FFI──▶ libMaaCore.so ──ADB──▶ 端末
```

- `apps/maa-server`：API サービス。ローカル開発時はフロントの静的配信も担当
- `apps/maa-web`：[windows-ui](https://github.com/virtualvivek/windows-ui)（MIT）コンポーネントのみで構成した静的フロント
- `docker/`：`Dockerfile.server`（adb と libatomic1 を含む）、`Dockerfile.web`

## クイックスタート（開発・検証のみ）

```bash
git clone https://github.com/Kasbuky-sudo/maa-docker-web.git
cd maa-docker-web
# deploy/ の docker-compose.yml と .env を使用
docker compose up -d
```

`http://<ホスト>:8080` を開きます。初回起動時に約 220MB のランタイムをダウンロードします（Runtime ページから手動実行も可）。

イメージ（マルチアーキ、main から自動ビルド）：

```text
ghcr.io/kasbuky-sudo/maa-server
ghcr.io/kasbuky-sudo/maa-web
```
