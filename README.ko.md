> ## ⚠️ 프로젝트 상태: 초기 개발 단계 — 아직 사용할 수 없습니다
>
> **운영 환경이나 일상 자동화에 사용하지 마세요.** 현재 활발히 개발 중이며 UI와 API가 예고 없이 바뀝니다. 또한 **실제 기기에서의 종단 간 태스크 실행은 한 번도 검증되지 않았습니다.**
> 현재 코드는 개발·실험·검증 용도로만 적합합니다. 자세한 내용은 [로드맵](#로드맵)과 [GitHub Issues](https://github.com/Kasbuky-sudo/maa-docker-web/issues)를 참고하세요.

[MAA(MaaAssistantArknights)](https://github.com/MaaAssistantArknights/MaaAssistantArknights) 공식
Linux 런타임을 **x86_64 / arm64** Docker 환경(NAS 친화)에서 동작하는 웹 관리 서비스로 감싼 프로젝트입니다.

이 저장소는 MAA 바이너리와 리소스를 **배포하지 않습니다**. 런타임은 MAA 공식 GitHub Release에서
다운로드하고 SHA-256으로 검증한 뒤 영구 볼륨에 저장합니다.

## 버전과 업데이트

| 버전 | 출처 | 설명 |
|---|---|---|
| 서버 버전 | `apps/maa-server/package.json` | **유일한 기준**: 제목 표시줄·설정·정보 페이지가 `GET /api/version` 을 통해 읽어 표시하며, 페이지별 하드코딩은 제거 |
| MAA 런타임 버전 | 디스크의 런타임(`data/runtime` 내 마커) | 독립적으로 업그레이드 가능: "업데이트 확인" 은 공식 최신 릴리스와 비교하고 **확인 후에만** 다운로드하며, 공식 `assets[].digest` 의 SHA-256 으로 검증 |

런타임 업그레이드에 이미지 재빌드는 필요하지 않습니다. 서버는 시작 시 마커를 읽고, 런타임이 교체되면
MaaCore 리소스 캐시를 무효화하고 기존 세션을 끊습니다.

## 되는 것 / 안 되는 것

✅ **구현됨**

- 멀티 아키텍처 이미지 빌드와 컨테이너 배포(`linux/amd64` + `linux/arm64`, CI 가 ghcr 에 게시)
- 공식 MAA 런타임 다운로드 / SHA-256 검증 / 압축 해제 / 상태 머신 / **공식 릴리스와의 버전 비교 및 업그레이드**
- Web UI 를 windows-ui 공식 컴포넌트로 **전면 재작성**하고 백엔드와 연결:
  홈, 작업 큐(12개 작업과 개별 설정), 자동 전투, 일정, 도구, 로그, 설정
- 백엔드 연동: 실행 상태 폴링(2.5초), 작업 설정 영구 저장, 큐 시작/정지,
  로그(HTTP + WebSocket 실시간), 연결 설정, 시스템 정보, 런타임/리소스 검증
- 연결 테스트: `AsstAsyncConnect`, **실기기(Meizu 16X 무선 ADB)에서 검증 완료**.
  엔드포인트는 즉시 반환하고 진행 상황은 상태 폴링으로 확인(게이트웨이 타임아웃 해소).
  성공 시 **세션을 유지**해 "시작" 에서 재사용합니다
- MaaCore 메시지 ID 를 런타임 동봉 바인딩으로 하나씩 대조했고, MaaCore 의 원문 메시지를 UI 에 표시
- 모바일 대응: 760px 이하 1열 배치, 공식 `collapsed-float` 드로어, 가로 스크롤 없음

- 인식 도구 **실구현**: 공개모집(Recruit) / 창고(Depot) / 오퍼레이터(OperBox)를 MaaCore 로 직접 실행하고, 결과는 공식 콜백 구조(RecruitResult / DepotInfo / OperBoxInfo) 로 표시. 실제 결과가 없을 때는 UI 에「예시 데이터」로 명시
- 자동 전투 **실구현**: 런타임에 포함된 76개 공식 작업 파일을 나열(SSS_/Paradox_ 접두사로 분류)하고, Copilot / SSSCopilot / ParadoxCopilot 프로토콜 필드로 실제 실행
- **이성 작전 주간 계획**: 요일별로 다른 스테이지를 지정하면 서버가 당일 스테이지로 Fight 작업을 확장
- **서버 측 스케줄러**: daily / weekdays / weekends / 요일 지정, 30초 tick, lastRun 중복 방지
- **디바이스 실시간 화면**: ADB screencap PNG 제공(실기기 1920×1080 검증). 모니터 페이지가 목표 FPS 로 갱신하며 실측 FPS 표시

❌ **미지원**

- **실기기에서 작업 실행의 종단 간 검증은 아직 없음**: 연결 ✓·세션 유지 ✓·주간 계획 확장 ✓ — "시작" 버튼이 이제 진짜입니다. 남은 것은 실기기에서 한 번의 전체 실행뿐
- MAA 작업 공유 사이트 온라인 검색 미연동(런타임 포함 작업과 로컬 파싱 파일만 사용 가능)
- 인식 도구의 "Penguin-Statistics / 도구상자로 내보내기" 미구현(결과는 UI 에 표시)
- 연결 설정 외의 설정은 서버에 저장되지 않음(`config.json` 화이트리스트는 4개 필드)
- **인증 없음**: 신뢰할 수 있는 LAN 에서만 사용하세요

## 구조

```text
브라우저 ──▶ maa-web (nginx) ──▶ maa-server (Node.js)
                                    ├── 런타임 관리(다운로드/검증/해제)
                                    ├── REST + WebSocket (로그·태스크·상태)
                                    └── runner ──koffi FFI──▶ libMaaCore.so ──ADB──▶ 기기
```

- `apps/maa-server`: API 서비스. 로컬 개발 시 프런트 정적 파일도 직접 제공
- `apps/maa-web`: [windows-ui](https://github.com/virtualvivek/windows-ui)(MIT) 컴포넌트로만 만든 정적 프런트
- `docker/`: `Dockerfile.server`(adb와 libatomic1 포함), `Dockerfile.web`

## 빠른 시작 (개발·검증 전용)

```bash
git clone https://github.com/Kasbuky-sudo/maa-docker-web.git
cd maa-docker-web
# deploy/ 의 docker-compose.yml 과 .env 사용
docker compose up -d
```

`http://<호스트>:8080` 접속. 첫 실행 시 약 220MB 런타임을 내려받으며 Runtime 페이지에서 수동 실행도 가능합니다.

이미지(멀티 아키, main 브랜치에서 자동 빌드):

```text
ghcr.io/kasbuky-sudo/maa-server
ghcr.io/kasbuky-sudo/maa-web
```
